# binary-hardening-bench

**测量一个二进制有多难被自动化逆向工具复刻。**

这个仓库提供一个可复现的测量方法：用四个逐级加固的样本，量化「自动化逆向工具从样本中恢复出业务秘密（密钥、字符串、算法逻辑）的能力」如何随加固强度下降。

结论先行 —— 同一段 license 校验逻辑，四级加固的复刻难度得分：

| 级别 | 样本 | 加固手段 | 复刻分 | 关键变化 |
|:---:|:---|:---|---:|:---|
| **L0** | `target.c` | 无（`/Od /Ob0`，关闭优化） | **100** | 密钥、成功串、失败串全部明文可见 |
| **L1** | `target-hard.c` | 字符串加密 + 常量碎片化 | **84** | 明文字符串从文件里彻底消失 |
| **L2** | `target-vm.c` | 字节码虚拟机 | **36** | 业务逻辑不在伪代码里，只剩 VM 分派循环 |
| **L3** | `target-vm5.c` | VM + 操作码运行期还原 | **26** | 字节码无法直接解析，需重跑 seed 派生才能读 |

分数越低 = 对手复刻越难。**从 100 到 26，降幅 74%。**

---

## 为什么需要这个

自动化逆向工具（反编译器 + 大模型）让「读懂一个二进制」的成本急剧下降。Ghidra 能在几十秒内把 `main` 反编译成可读的 C 伪代码，大模型能直接解释它的逻辑。

如果你的软件里有一个关键算法或密钥，**问题不是「能不能被逆向」——答案永远是能——而是「逆向需要多少自动化工作量」**。

这个仓库不提供防护盾，它提供的是一把尺子：让你能测量自己的加固到底有没有用，以及有用了多少。

## 核心发现

### 1. 字符串加密能消灭明文，但消灭不了可读性

L1 让三个核心秘密（KEY / OK 串 / FAIL 串）在二进制里的出现次数从 1 变成 **0**。字符串扫描彻底失效。

但反编译器依然把解密函数完整还原出来：

```c
local_18 = DAT_140022000 ^ DAT_140022001;
for (i = 0; i < 15; i++)
    *(byte *)(param_2 + i) = *(byte *)(param_1 + i) ^ local_18;
    local_18 += cVar1;
```

**对手照着抄一遍就解开了。** 字符串加密只是把秘密从 `.rdata` 搬到了 `.text`，没有改变「秘密可以被静态计算出来」这个本质。

> 教训：能在伪代码里读到的加密，等于没加密。

### 2. 虚拟化是分水岭 —— 秘密不再出现在伪代码里

L2 把业务逻辑编译成自定义字节码，交给一个栈式解释器执行。反编译器看到的不再是 license 校验，而是一个 15 个 case 的 `switch` 分派循环。

`main` 函数里**没有任何业务字符串**，`referenced_strings` 只剩一个 `"usage: ..."`。字节码以长度为 `0x27` 的不透明常量传入：

```c
iVar1 = FUN_140001190(0x1400173f0, 0x27, &DAT_140022b60);
```

对手即使读懂了 14 个操作码的语义，拿到的也只是「一个解释器」。**要恢复业务逻辑，必须先提取字节码，再手工翻译成伪代码。** 这一步无法自动化——因为字节码格式是你自己定的。

### 3. 操作码置换让字节码本身不可读

L3 在 L2 之上加了运行期操作码还原。反编译结果里唯一的变化是一行：

```c
// L2: switch(*(char *)(param_1 + (int)local_88))
// L3: switch(param_3[(ulonglong)*(byte *)(param_1 + (int)local_88) + 0x148])
```

字节值不再直接是操作码，而要查一张运行期生成的 256 字节逆置换表。**文件里读到的字节序列，没有意义。**

要还原它，对手必须：读出 `derive_seed()` 的全部常量 → 重跑 xorshift 雪崩 → 重放 Fisher-Yates → 求逆置换。能做，但这是**为每个样本单独写一份分析脚本**，不再是「跑一遍 Ghidra」。

## 怎么用

### 测量你自己的样本

工具链不绑定任何具体产品：通过 `REA_CMD` 环境变量注入逆向工具的 MCP 启动命令。

```bash
# 0. 配置逆向工具（任意支持 MCP 的逆向/反编译工具）
export REA_CMD="node /path/to/reverse-tool.mjs mcp"

# 1. 让逆向工具分析样本，落原始观测日志
node telemetry/probe.mjs path/to/your.exe my-sample

# 2. 算分
node telemetry/score.mjs my-sample.raw.jsonl

# 3. 与基线对比（看你的加固到底改善了多少）
node telemetry/score.mjs --diff my-sample.raw.jsonl telemetry/vm53-baseline.raw.jsonl

# 可选：深挖单个函数（伪代码 + 引用串 + 被调函数）
node telemetry/look.mjs path/to/your.exe 0x140001480
```

`REA_CMD` 会被按空格切分为 `[命令, ...参数]`。路径含空格时请自行加引号并调整切分结果，或改用无空格的安装路径。

### 复现本仓库的四级样本

需要 MSVC（`cl.exe`）与 Node.js。

```bash
cd lab
# L0
cmd //c build-clear.bat
# L1
cmd //c build-hard.bat
# L2
cmd //c build-vm.bat
# L3（先运行生成器产出字节码，再编译）
node gen-vm5.mjs && cmd //c build-vm5.bat
```

四个样本行为完全一致：
- 正确序列号 → 退出码 `0`，输出 `LICENSE_OK: access granted`
- 错误序列号 → 退出码 `1`，输出 `LICENSE_FAIL: invalid serial`
- 无参数 → 退出码 `2`

正确序列号是 15 字节原始二进制（见 `lab/serial.txt`），**不是十六进制文本**。用 shell 传递会被引号污染，请用 `spawnSync` 之类的接口直接传 buffer。

## 评分模型

`score.mjs` 的核心思想：**不看加固做了多少，只看对手取得秘密需要多少自动化程度。**

三档判定：

| 判定 | 含义 | 分数区间 |
|:---|:---|:---|
| 明文泄漏 | 秘密字符串直接出现在二进制里，`strings` 一把梭 | 70–100 |
| 可抄的解密逻辑 | 伪代码里有完整解密循环，照抄即得 | 55–72 |
| 已虚拟化 | 业务逻辑不在伪代码里 | 30–38 |
| 需运行期还原 | 连字节码本身都不可直接解析 | 16–26 |

同时统计算法指纹（`xor_immediate` / `rolling_key` / `byte_compare_loop` / `strlen_call` / `key_index` / `vm_dispatch` / `vm_table`）作为辅助证据。

**重要**：这个分数是相对指标，只适合同一赛道内的样本对比。它不预测「真实攻击者需要多久」，只衡量「自动化工具链在多大程度上能直接拿到秘密」。

## 诚实的局限

这些东西必须说清楚，否则会误导人。

### 1. 完全不防动态分析

在 `vm_run` 下断点，dump `vm.buf[]`，**全部静态保护立刻失效**。这个仓库里的四级加固只针对静态分析（反编译器 + 字符串扫描），对调试器毫无抵抗。

补反调试（`IsDebuggerPresent`、时序检测、自校验）是另一个独立课题，本仓库未覆盖。

### 2. L3 的种子取自编译期常量

`derive_seed()` 的输入全是编译期常量，所以从源码重建出的二进制**行为完全可预测**——这对做对照实验是优点，对真实防护是缺点。读过源码的人可以离线复算置换表。

真实场景应当掺入运行期变量（PE 时间戳、导入表散列、TLS 时序等），使每个副本的置换表都不同。

### 3. 解释器的 case 分支是可读的

15 个操作码的语义在反编译结果里全部可见。**手工打表翻译字节码是可行的**，只是不能自动化。L3 提高的是「每个样本的边际分析成本」，不是「不可能」。

### 4. 样本是刻意简化的

`target.c` 是一个 15 行验证逻辑的玩具。真实软件的加固收益会因复杂度、调用图规模、优化等级而不同。这里的数字证明的是**方法有效**，不是「你的软件加固后就是 26 分」。

### 5. 编译选项影响巨大

所有样本都用 `/Od /Ob0`（关闭优化）编译，为了让分析结果可比。开启 `/O2` 后反编译质量会显著下降，基线分数本身就会变化。**跨编译选项的分数不可比。**

```

  target.c               L0 基线：明文秘密

```

## 工具链说明

`probe.mjs` / `rea-tap.mjs` 通过 MCP 协议与逆向工具通信，采用 stdio 透明代理方式，不修改被调用方任何文件。

虽然当前适配置的是 REA，但代理层是**协议无关**的 —— 任何 MCP 形态的逆向工具只要替换启动命令即可接入。评分器 `score.mjs` 直接消费 JSON-RPC 日志，不依赖具体工具。

设计上刻意保持了这条边界：**测量逻辑与工具实现解耦**。

## 这个仓库不是什么

- 不是加壳工具。它不提供「把任意 exe 变加固」的能力——四个样本是针对同一个业务逻辑手工写的。换业务要重写字节码。
- 不是通用防护方案。它测量的是**静态分析成本**，一个维度而已。
- 不是安全保证。任何加固都只是提高成本，不改变「逆向在原理上永远可行」。

它是一把尺子和四个刻度量好的砝码。尺子能精确告诉你对手复刻你有多难，砝码证明从 100 分压到 26 分这条路走得通。它还不会自己造砝码。
