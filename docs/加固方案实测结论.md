# 二进制加固方法 · 实测结论文档

> 目标：让对手拿着**自动化逆向工具**（反编译器 + 大模型）也**复刻不出**目标的业务秘密。
> 方法：不改工具，而是让**被分析的样本**在自动分析管线里失去可读性。
> 全部结论均来自实测，非推测。

---

## 一、核心结论

自动化逆向工具的穿透力，取决于它能拿到多少**可自动化的语义**。按逆向成本分级：

| 级别 | 样本形态 | 对手拿到什么 | 复刻分 | 取得秘密的成本 |
|---|---|---|---|---|
| L0 | 无加固 | 明文密钥 + 明文判断串 | **100** | 字符串搜索，秒级 |
| L1 | 字符串加密 | 伪代码里完整可读的 `decode()` | **84** | 抄函数离线跑，分钟级 |
| L2 | L1 + 控制流虚拟化 | 通用解释器 + 不透明字节码 | **36** | 手工还原操作码语义，小时级 |
| L3 | L2 + 操作码运行期还原 | 解释器 + **需要先跑密钥派生的**字节码 | **26** | 还原语义 + 重建置换表，半天级 |

**关键洞察**：加固不是让工具"看不到"，而是让它**看到的东西无法直接复用**。
反编译器一定会输出伪代码；能不能挡住复刻，取决于这份伪代码是"秘密本身"还是"秘密的容器"。

## 二、四个靶子的实测数据

靶子语义完全一致（`target.c` 原始逻辑）：

```c
if (strlen(in) != strlen(KEY)) return 0;
for (i = 0; i < n; i++)
    if ((in[i] ^ 0x5A) != KEY[i]) return 0;
return 1;
```

正确序列号（15 字节原始二进制，非十六进制文本）：
`08 1f 1b 77 0e 1b 08 1d 1f 0e 77 68 6a 68 6c`

| 样本 | 文件 | 大小 | sha256 前16 | 复刻分 | 明文 | 逻辑指纹 | VM指纹 | 运行期还原 | 伪码总量 |
|---|---|---|---|---|---|---|---|---|---|

## 三、逐层加固技术细节

### L1 · 字符串加密（`target-hard.c`）

- 三组密文数组：`ENC_KEY` / `ENC_OK` / `ENC_BAD`
- 加密规则：`c[i] = p[i] ^ (SEED + i * STEP)`，`SEED = 0x2f ^ 0x24 = 0x0B`，`STEP = 0x03`
- 常量碎片化：`0x37 ^ 0x6d = 0x5A`，避免立即数出现在伪代码里

**为什么不够**：`decode()` 被 Ghidra 完整还原——
```c
local_18 = DAT_140022000 ^ DAT_140022001;
*(byte*)(param_2+i) = *(byte*)(param_1+i) ^ local_18;
local_18 += cVar1;
```
对手照抄这个函数就能离线解出全部明文。**只要有可读伪代码，Ghidra 就能还原。**

### L2 · 控制流虚拟化（`target-vm.c` = A4）

- 栈式字节码 VM，17 个操作码
- `main` 只剩：`strncpy` → 一次 `FUN(vm_run)` 调用 → 两路 `printf`
- 39 字节字节码作为**不透明立即数**传入解释器
- 业务字符串在解释器内解密到栈上，`main` 里没有任何字面量

**Ghidra 实测看到的分派语句**：
```c
switch(*(char *)(param_1 + (int)local_88))
```
→ 15 个 case 全可见：`'\x11'`=LOADK、`'3'`=STRLEN、`'D'`=CMP、`'U'`=JZ、
`'w'`=GETBYTE、`-0x78`=GETKEY、`-0x67`=XORI、`-0x45`=JMP、`-0x34`=RET。

**已消除**：`referenced_strings = 0`，`referenced_names` 89 条全是函数引用与跳转标签（`switchD_14000125d::caseD_22`），**零价值信息**。

**剩余缺口**：字节值直接就是操作码，读文件即用。

### L3 · 操作码运行期还原（`target-vm5.c` = A5）

在 L2 之上加两层：

**① 字节码流加密**
```c
static int unpack_program(const unsigned char *enc, unsigned char *out, int cap, unsigned int seed) {
    int n = enc[0];
    unsigned int x = seed ^ 0xa5a5a5a5u;
    for (int i = 0; i < n; i++) {
        x ^= x << 13; x ^= x >> 17; x ^= x << 5;
        out[i] = (unsigned char)(enc[1 + i] ^ (unsigned char)(x >> 3));
    }
    return n;
}
```

**② 操作码置换（运行期生成）**
- `derive_seed()`：混入编译期常量（数组长度、元素值）做 4 轮 xorshift 雪崩
- `build_perm()`：以 seed 为伪随机源做 Fisher-Yates，得 256 字节双射
- 字节码里存 `perm[real_op]`；解释器用 `inv[raw]` 还原

**Ghidra 实测看到的分派语句**（这是 A5 唯一的实质差异）：
```c
switch(param_3[(ulonglong)*(byte *)(param_1 + (int)local_88) + 0x148])
```
`param_3 + 0x148` 就是 `vm->inv[]`。对手即使读懂全部 14 个 case 的语义，
拿到的字节码也**无法直接解析**——必须先重跑 `derive_seed → build_perm → 求逆`。

**③ 密文碎片化**
39 字节密文拆成 `SEG_A..SEG_D` 四段，由 `seg_byte()` 按 `lens[]` 顺序重组，
避免"整段 byte-scan 抓走"。

## 四、已知缺陷（诚实记录）

1. **4 段 10 字节碎片在文件里仍能单独命中**。`/Od /Ob0` 关闭优化，编译器把
   `SEG_A..D` 原样放在数据段。对手可凑出密文，只是要额外理解 `seg_byte` 的拼接
   顺序。彻底封法：让碎片在运行期才可还原（从 `.reloc` / TLS / 时间派生）。

2. **解释器语义本身没有保护**。14~15 个 case 全部可读，对手手工打表是可行的。
   要真正封死，需操作码语义混淆（如把 switch 拆成多级间接跳转 + 假分支）。

3. **`derive_seed()` 的输入是编译期常量**。对手若完整读过源码级逻辑，理论可复算。
   真实场景应改为运行期输入（如 PE 时间戳、导入表散列、TLS 回调时序）。

4. **所有加固均不防动态分析**。对手用调试器直接在 `vm_run` 断点、dump 解密后的
   `vm.buf[]`，可绕过全部静态保护。本方案只针对 **静态分析管线**。

## 五、测量工具链

位于 `telemetry/`：

| 文件 | 作用 |
|---|---|
| `rea-tap.mjs` | MCP stdio 透明代理，双向落 NDJSON。`REA_TAP_LOG` 指定日志，绝不抛异常 |
| `probe.mjs` | 固定 7 步探针：`open_binary → binary_overview → list_strings → search_strings×2 → list_procedures → analyze_function × N`。`REA_PROBE_FUNCS` 控制采样数（默认 10，环境变量名沿用历史命名） |
| `score.mjs` | **成本模型评分器**，输出复刻分 0-100 + 明文泄漏 + 逻辑/VM 指纹 + `needs_runtime_decode`。支持 `--diff a b` |
| `look.mjs` | 单函数深挖：拉取指定地址的伪代码、引用串、被调函数 |
| `smoke.mjs` | 握手冒烟测试（验证代理透明转发） |

### 用法

```bash
# 采样一个样本
REA_PROBE_FUNCS=10 node probe.mjs ../lab/target-vm5.exe vm5-raw

# 打分
node score.mjs vm5-raw.raw.jsonl

# 差分
node score.mjs --diff clear3-raw.raw.jsonl vm53-raw.raw.jsonl

# 深挖某个函数
node look.mjs "lab/target-vm5.exe" 0x140001480
```

| 版本 | 依据 | 问题 |

## 七、给未来的自己：踩过的坑

1. **所有工具返回统一 Evidence 信封**，真实数据在 `normalized_result`，不在顶层。
2. **`evidence_id` 是内容派生哈希**（`ev_${digestCanonicalValue(...)}`）。
   工具承诺 `import_mode: "ephemeral-source-immutable"`（不改源文件），
   所以加固落在文件字节即生效；但伪造证据必然自证矛盾。
3. **Ghidra 完全不做 MSVC 符号恢复**：`check_serial` 永远显示为 `FUN_140001000`。
4. **`list_procedures` 不返回函数体大小**，无法按大小排序。用户代码总在 `.text`
   最前面，CRT 在后——按地址取前 N 个，N 要够大（A5 的 `vm_run` 排第 7 位，N=4/5 会漏）。
5. **`JZ` 用 `peek` 不 `pop` 会造成栈泄漏**：A4 初版每轮循环泄漏一个栈槽，到 i=6 时
   栈满（上限 16），`push` 静默丢弃，比较结果丢失 → 必然走失败分支。这个 bug 花了
   近一小时定位，靠给解释器加 trace 才看到 `sp` 单调递增。
6. **跨盘备份必须校验**：第一次用 `mv` 被中断，D 盘只落了 2765/7194 文件。
   改 `robocopy /E /COPY:DAT /MT:16` 后 SHA256 逐文件全等。
7. **往 C 文件注入含 `\n` 的代码时，多层 shell/JS/heredoc 转义会反复失败**
   （`C2001: 常量中有换行符`）。解法：写独立头文件用宏 + `fputc(10, stderr)` 绕开转义。
